# ESP8266-Autowatering2 — контроллер автополива растений

Прошивка для ESP8266 (NodeMCU / Wemos D1 mini, 4 МБ flash): **4 канала помп**,
**дискретный датчик низкого уровня воды**, веб-интерфейс прямо с устройства,
расписание полива с сохранением в энергонезависимой памяти.

* Версия прошивки: **1.0.0**
* Готовый бинарник: [`firmware/autowatering-esp8266.bin`](firmware/autowatering-esp8266.bin)
* Для других ИИ/разработчиков: [`ReadAI.md`](ReadAI.md)

---

## Возможности

| Требование | Реализация |
|---|---|
| Подключение к Wi-Fi, при отсутствии настроек — точка доступа | Если SSID не задан (или подключиться не удалось за 25 с), поднимается открытая точка `AutoWater-XXXXXX` с captive portal и страницей настройки Wi-Fi |
| Время и датчик уровня в шапке | Часы (`чч:мм:сс` + дата) по NTP и индикатор «уровень воды: ОК / НИЗКИЙ» |
| Задачи полива | Время старта, длительность (сек), период повторения (дни), активность, статус, время последнего и следующего полива, кнопка ручного пуска |
| Сохранение задач и статусов | Всё лежит в EEPROM-секторе (CRC32): настройки, задачи, `lastRun`, `nextDue` |
| Ручное управление каналами | Вкладка «Каналы»: пуск на N секунд и остановка для каждого из 4 каналов |
| Настройки | Wi-Fi, пины помп (+ инверсия), пин датчика и полярность сигнала, NTP, часовой пояс, предохранители |

Ручной пуск задачи **не меняет** её расписание и статус — помпа просто работает
заданную в задаче длительность.

## Аппаратная часть

### Пины по умолчанию

| Назначение | GPIO | Плата (NodeMCU) | Почему так |
|---|---|---|---|
| Помпа 1 | GPIO4  | D2 | при старте ESP8266 — низкий уровень |
| Помпа 2 | GPIO5  | D1 | при старте — низкий уровень |
| Помпа 3 | GPIO12 | D6 | при старте — низкий уровень |
| Помпа 4 | GPIO14 | D5 | при старте — низкий уровень |
| Датчик уровня | GPIO13 | D7 | низкий уровень = «вода на исходе», внутренняя подтяжка к +3.3 В |

Пины выбраны специально: **при включении питания на них 0 В**, поэтому реле не
щёлкают при подаче питания (при настройке по умолчанию, без инверсии).
Пины GPIO0, GPIO2, GPIO15 при старте находятся в высоком уровне — их лучше не
использовать для помп (в интерфейсе их можно выбрать, но будьте осторожны).
GPIO6…GPIO11 заняты flash и запрещены.

### Подключение

```
ESP8266 3V3 ── VCC модуля реле (если реле 3.3 В)      ESP8266 GND ── GND
ESP8266 5V  ── VCC модуля реле (если реле 5 В, питание от USB)
GPIO4/5/12/14 ── IN1..IN4 модуля реле
GPIO13 ── сигнал датчика уровня (поплавок/геркон), второй контакт датчика ── GND
```

* Модуль реле на 4 канала (обычно активный **низкий** уровень — включите
  «Инверсию» в настройках, тогда помпа включается низким уровнем).
* Датчик уровня: поплавковый геркон, который **замыкается на GND**, когда вода
  заканчивается → полярность «низкий уровень = вода на исходе» включена по
  умолчанию. Если у вас датчик с обратной логикой — снимите галочку.
* Помпы питаются от отдельного источника; ESP8266 и реле должны иметь общий GND.
* Не питайте помпы от 3.3 В стабилизатора платы.

## Первый запуск

1. Прошейте плату (см. ниже) и подайте питание.
2. Если Wi-Fi не настроен, устройство поднимает **открытую** сеть
   `AutoWater-XXXXXX` (XXXXXX — часть ChipID). Пароля нет: сеть нужна только для
   настройки.
3. Подключитесь к ней телефоном/ноутбуком — страница настройки откроется
   автоматически (captive portal). Если не открылась, зайдите на
   `http://192.168.4.1/`.
4. Вкладка **Настройки → Wi-Fi**: укажите SSID и пароль вашей сети 2.4 ГГц,
   нажмите «Сохранить Wi-Fi и перезагрузить».
5. После перезагрузки устройство подключится к роутеру; IP-адрес будет показан
   в шапке (и в логе Serial 115200). Открывайте интерфейс по этому адресу.

## Интерфейс

### Шапка
Текущее время и дата (NTP), состояние датчика уровня воды, режим Wi-Fi и IP.
Если Wi-Fi не настроен или время не синхронизировано — показывается баннер.

### Вкладка «Задачи»
* Форма добавления/редактирования: канал, время старта, длительность (сек),
  период (дни), флажок «Задача активна».
* Карточка задачи: время, длительность, период, статус
  (`ожидание / полив / выключена / нет времени`), время последнего и следующего
  полива.
* Кнопки: **▶ Пуск** (ручной пуск на настроенную длительность, статус не
  меняется), **Изменить**, **Удалить**.
* Максимум 8 задач.

Логика расписания:

* задача срабатывает в указанное время суток каждые `период` дней;
* если устройство было выключено в плановое время, полив выполнится при
  включении, но не позже `Догоняющий полив` часов после планового времени
  (по умолчанию 6; 0 — строго по расписанию);
* пропущенные «слишком поздние» поливы не выполняются, расписание сдвигается на
  следующий период (без накопления долгов);
* пока время не синхронизировано по NTP, задачи не запускаются (статус
  «нет времени»).

### Вкладка «Каналы»
Для каждого канала: состояние, остаток времени, поле «секунды» и кнопки
**▶** (пуск на N секунд) и **Стоп**.

### Вкладка «Настройки»
* **Wi-Fi** — SSID/пароль, сохранение с перезагрузкой.
* **Помпы** — GPIO для каждого канала и инверсия (включение низким уровнем).
* **Датчик уровня** — GPIO, внутренняя подтяжка, полярность сигнала, запрет
  полива при низком уровне.
* **Время и защита** — NTP-сервер, смещение от UTC в минутах (Нидерланды: 60
  зимой / 120 летом), максимум секунд на включение, догоняющий полив.
* **Информация** — версия, режим Wi-Fi, IP, сырое значение датчика, память, uptime.
* **Опасная зона** — перезагрузка и сброс к заводским настройкам.

## Защита и предохранители

* **Низкий уровень воды** — пуск блокируется, а начатый полив немедленно
  прекращается (если включена опция «Блокировать полив при низком уровне»).
* **Максимальная длительность** (`maxRunSec`, по умолчанию 600 с) — жёсткое
  ограничение на любое включение канала, включая ручное и по задаче.
* **Аварийное выключение при потере питания** — после перезагрузки все каналы
  выключены (реле обесточены).

## REST API

Все запросы — `application/x-www-form-urlencoded`, ответы — JSON.

| Метод | URL | Параметры | Назначение |
|---|---|---|---|
| GET | `/api/state` | — | Время, датчик, Wi-Fi, каналы, задачи |
| GET | `/api/config` | — | Настройки |
| POST | `/api/task` | `id` (-1 = новая), `ch`, `hour`, `min`, `dur`, `period`, `enabled` | Создать/изменить задачу |
| POST | `/api/task/del` | `id` | Удалить задачу |
| POST | `/api/task/run` | `id` | Ручной пуск задачи |
| POST | `/api/ch` | `ch`, `sec` (0 = стоп) | Ручной пуск/остановка канала |
| POST | `/api/config` | `chN_pin`, `chN_inv`, `sensorPin`, `sensorInv`, `sensorPull`, `blockLow`, `maxRun`, `catchup`, `ntp`, `tz` | Сохранить настройки |
| POST | `/api/wifi` | `ssid`, `pass` | Сохранить Wi-Fi и перезагрузиться |
| POST | `/api/factory` | — | Сброс к заводским настройкам |
| POST | `/api/reboot` | — | Перезагрузка |

Ошибки: `{"ok":false,"error":"low_water"}` (HTTP 409) и подобные.

## Хранение настроек

Настройки и задачи хранятся одной структурой `Store` (см. `src/app_config.h`) в
секторе эмуляции EEPROM, защищённой CRC32 и magic-числом. При первом старте или
повреждении данных автоматически восстанавливаются умолчания.

Сохраняется в том числе:

* `lastRun` — время последнего полива задачи (это и есть «статус»);
* `nextDue` — время следующего планового полива (чтобы расписание не «плыло»
  после перезагрузки).

## Сборка

### Вариант 1: PlatformIO (рекомендуется)

```bash
pio run                # сборка
pio run -t upload      # прошивка (порт COM7, 921600 — см. platformio.ini)
pio device monitor     # лог 115200
```

`tools/pio_embed_web.py` автоматически пересобирает `src/page_html.h` из
`web/index.html` перед сборкой.

### Вариант 2: `tools/build_firmware.sh` (без PlatformIO)

Скрипт собирает прошивку напрямую кросс-компилятором xtensa-lx106-elf-g++ и
ядром Arduino-esp8266 2.4.2 (именно так собран бинарник в `firmware/`):

```bash
TOOLCHAIN_DIR=$HOME/tools/xtensa-lx106-elf \
CORE_DIR=$HOME/tools/Arduino-2.4.2 \
./tools/build_firmware.sh
```

Результат: `firmware/autowatering-esp8266.bin` + `firmware/build-info.txt`.

### Правка интерфейса

Интерфейс — `web/index.html` (чистый HTML/CSS/JS, без сборщиков), упаковывается
в `src/page_html.h` gzip-ом:

```bash
python3 tools/embed_web.py
```

### Тесты логики (без железа)

```bash
make -C tests/host run      # storage/CRC, помпы, датчик, планировщик
```

## Прошивка

```bash
pip install esptool
./tools/flash.sh            # COM7, 921600
./tools/flash.sh /dev/ttyUSB0 460800
```

Windows: `tools\flash.bat` (по умолчанию COM7, 921600).

Или вручную:

```bash
esptool.py --chip esp8266 --port COM7 --baud 921600 \
  write_flash --flash_mode dout --flash_freq 40m --flash_size 4MB \
  0x00000 firmware/autowatering-esp8266.bin
```

Образ уже содержит загрузчик `eboot` (адрес 0x0) и приложение (адрес 0x1000),
поэтому прошивается одним файлом с `0x00000`.

После прошивки: Serial 115200, скорость загрузки 921600 (в `platformio.ini`).

## Структура репозитория

```
src/
  main.cpp          точка входа, setup()/loop()
  app_config.h      константы, умолчания, структуры хранения
  storage.*         EEPROM: загрузка/сохранение/CRC/сброс
  channels.*        помпы (4 канала) + датчик уровня, защита по времени/уровню
  scheduler.*       расписание задач, расчёт next/last, статусы
  netmgr.*          Wi-Fi (STA/AP/captive portal), NTP, перезагрузка
  webui.*           HTTP-сервер, REST API
  page_html.h       сгенерированный (gzip) веб-интерфейс
web/index.html      исходник интерфейса
tools/
  embed_web.py      web/index.html -> src/page_html.h
  build_firmware.sh сборка без PlatformIO
  elf2bin.py        eboot + sketch -> единый .bin
  flash.sh          прошивка через esptool
firmware/           готовый бинарник и сводка о сборке
```

## Ограничения

* Часовой пояс задаётся смещением от UTC **целым числом часов** для SNTP ядра
  2.4.2 (в ядре 3.x — с точностью до минуты); переход на летнее время
  автоматически не выполняется — при необходимости поменяйте смещение вручную.
* Без синхронизации времени задачи не выполняются (нет «железных» часов RTC).
* Задачи — до 8 штук, каналы — 4.
* Web-интерфейс без авторизации: поднимайте устройство в доверенной сети.
