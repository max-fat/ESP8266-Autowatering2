# ESP8266-Autowatering2 — контроллер автополива растений

Прошивка для ESP8266 (NodeMCU / Wemos D1 mini, 4 МБ flash): **4 канала помп**,
**дискретный датчик низкого уровня воды**, веб-интерфейс прямо с устройства,
расписание полива с сохранением в энергонезависимой памяти.

* Версия прошивки: **1.6.1**
* Готовый бинарник: [`firmware/autowatering-esp8266.bin`](firmware/autowatering-esp8266.bin)
* Страница проекта для тех, кто хочет просто скачать: [`docs/index.html`](docs/index.html)
  (описание, скриншоты, установка и **прошивка по USB прямо из браузера** — открывается через GitHub Pages)
* Для других ИИ/разработчиков: [`ReadAI.md`](ReadAI.md)

---

## Возможности

| Требование | Реализация |
|---|---|
| Подключение к Wi-Fi, при отсутствии настроек — точка доступа | Если SSID не задан (или подключиться не удалось за 25 с), поднимается открытая точка `AutoWater-XXXXXX` с captive portal и страницей настройки Wi-Fi |
| Выбор сети из списка | Кнопка **«Сканировать»** рядом с полем SSID (в настройках и в баннере режима настройки): контроллер находит сети вокруг, имя подставляется в поле по нажатию; пароль вводится вручную |
| Время и датчик уровня в шапке | Часы (`чч:мм:сс` + дата) и индикатор «уровень воды: ОК / НИЗКИЙ» |
| Время при открытии с телефона | Кнопки «Время с телефона» / «Время и пояс с телефона» — браузер передаёт `Date.now()` (и свой часовой пояс) на контроллер, у которого нет часов с батарейкой |
| Задачи полива | Время старта, длительность (сек), период повторения (дни), активность, статус, время последнего и следующего полива, кнопка ручного пуска |
| Сохранение задач и статусов | Всё лежит в EEPROM-секторе (CRC32): настройки, задачи, `lastRun`, `nextDue` |
| Ручное управление каналами | Вкладка «Каналы»: пуск на N секунд и остановка для каждого из 4 каналов |
| Резервная копия и перенос | Вкладка «Настройки» → «Скачать файл настроек» сохраняет настройки и задачи в JSON; «Загрузить из файла» переносит их на другой модуль (Wi-Fi в файл не входит) |
| Имена модуля и каналов | Имя модуля («Теплица», «Балкон») видно в шапке, в заголовке вкладки браузера и в имени точки доступа; у каждого канала своё имя — что он поливает («Орхидеи», «Томаты»). Имя выводится рядом с номером канала: «Канал 1 · Орхидеи» — на вкладках «Каналы» и «Задачи», в уведомлениях и в списке выбора канала |
| Обновление прошивки по Wi-Fi | Вкладка «Настройки» → «Обновление прошивки»: выбираете `firmware/autowatering-esp8266.bin`, нажимаете «Обновить прошивку» — файл уходит на контроллер по сети, тот пишет его во flash и перезагружается сам. Кабель, esptool и Arduino IDE не нужны; настройки, задачи и имена каналов сохраняются |
| Обновление всех модулей из одного места | «Настройки» → «Другие модули в сети»: поиск автополивов в домашней сети, их версии и обновление выбранного по Wi-Fi. Сканер работает прямо из браузера: он спрашивает `/api/ident` у адресов подсети, файл прошивки уходит на `POST /api/ota` выбранного модуля. Видны модули с 1.6.2 и новее |
| Настройки | Wi-Fi, пины помп (+ инверсия), имена каналов, пин датчика и полярность сигнала, NTP, часовой пояс, предохранители |

Ручной пуск задачи **не меняет** её расписание и статус — помпа просто работает
заданную в задаче длительность.

## Аппаратная часть

### Пины по умолчанию

| Назначение | GPIO | Плата (NodeMCU) | Почему так |
|---|---|---|---|
| Помпа 1 | GPIO4  | D2 | при старте ESP8266 — низкий уровень |
| Помпа 2 | GPIO5  | D1 | при старте — низкий уровень |
| Помпа 3 | GPIO12 | D6 | при старте — низкий уровень |
| Помпа 4 | GPIO14 | D5 | при старте — низкий уровень |
| Датчик уровня | GPIO13 | D7 | низкий уровень = «вода на исходе», внутренняя подтяжка к +3.3 В |

Пины выбраны специально: **при включении питания на них 0 В**, поэтому реле не
щёлкают при подаче питания (при настройке по умолчанию, без инверсии).
Пины GPIO0, GPIO2, GPIO15 при старте находятся в высоком уровне — их лучше не
использовать для помп (в интерфейсе их можно выбрать, но будьте осторожны).
GPIO6…GPIO11 заняты flash и запрещены.

### Подключение

```
ESP8266 3V3 ── VCC модуля реле (если реле 3.3 В)      ESP8266 GND ── GND
ESP8266 5V  ── VCC модуля реле (если реле 5 В, питание от USB)
GPIO4/5/12/14 ── IN1..IN4 модуля реле
GPIO13 ── сигнал датчика уровня (поплавок/геркон), второй контакт датчика ── GND
```

* Модуль реле на 4 канала (обычно активный **низкий** уровень — включите
  «Инверсию» в настройках, тогда помпа включается низким уровнем).
* Датчик уровня: поплавковый геркон, который **замыкается на GND**, когда вода
  заканчивается → полярность «низкий уровень = вода на исходе» включена по
  умолчанию. Если у вас датчик с обратной логикой — снимите галочку.
* Помпы питаются от отдельного источника; ESP8266 и реле должны иметь общий GND.
* Не питайте помпы от 3.3 В стабилизатора платы.

## Первый запуск

1. Прошейте плату (см. ниже) и подайте питание.
2. Если Wi-Fi не настроен, устройство поднимает **открытую** сеть
   `AutoWater-XXXXXX` (XXXXXX — часть ChipID). Пароля нет: сеть нужна только для
   настройки.
3. Подключитесь к ней телефоном/ноутбуком — страница настройки откроется
   автоматически (captive portal). Если не открылась, зайдите на
   `http://192.168.4.1/`.
4. Вкладка **Настройки → Wi-Fi**: нажмите «Сканировать» и выберите свою сеть из
   списка (пароль вводится вручную), затем сохраните — устройство перезагрузится
   нажмите «Сохранить Wi-Fi и перезагрузить».
5. После перезагрузки устройство подключится к роутеру; IP-адрес будет показан
   в шапке (и в логе Serial 115200). Открывайте интерфейс по этому адресу.

## Интерфейс

### Шапка
Текущее время и дата (NTP), состояние датчика уровня воды, режим Wi-Fi и IP.
Если Wi-Fi не настроен или время не синхронизировано — показывается баннер.

### Вкладка «Задачи»
* Форма добавления/редактирования: канал, время старта, длительность (сек),
  период (дни), флажок «Задача активна».
* Карточка задачи: время, длительность, период, статус
  (`ожидание / полив / выключена / нет времени`), время последнего и следующего
  полива.
* Кнопки: **▶ Пуск** (ручной пуск на настроенную длительность, статус не
  меняется), **Изменить**, **Удалить**.
* Максимум 8 задач.

Логика расписания:

* задача срабатывает в указанное время суток каждые `период` дней;
* если устройство было выключено в плановое время, полив выполнится при
  включении, но не позже `Догоняющий полив` часов после планового времени
  (по умолчанию 6; 0 — строго по расписанию);
* пропущенные «слишком поздние» поливы не выполняются, расписание сдвигается на
  следующий период (без накопления долгов);
* пока время не синхронизировано по NTP, задачи не запускаются (статус
  «нет времени»).

### Вкладка «Каналы»
Для каждого канала: заголовок «Канал N · Имя» (у канала без имени — просто «Канал N»),
GPIO, состояние, остаток времени,
поле «секунды» и кнопки **▶** (пуск на N секунд) и **Стоп**.

При пуске появляется уведомление «Канал N · Имя: включён на X с», а когда время
истекает — «Канал N · Имя: полив завершён (X с)». Если помпу остановил датчик,
уведомление будет «Канал N · Имя: остановлен — низкий уровень воды»; ручная остановка
тоже подтверждается уведомлением (поэтому событие с устройства не дублируется).

### Вкладка «Настройки»
* **Модуль** — имя контроллера и кнопка «Сохранить имя». Имя показывается в шапке
  и в заголовке вкладки браузера, а также становится префиксом точки доступа
  (`Теплица-A1B2C3` вместо `AutoWater-A1B2C3`) — это и помогает различить два
  модуля в списке сетей телефона. Пустое имя = «Автополив».
* **Wi-Fi** — SSID/пароль, сохранение с перезагрузкой. Кнопка **«Сканировать»**
  запускает поиск сетей на контроллере: найденные сети показываются списком
  (имя, 🔒 и уровень сигнала, сильные сверху); нажатие на сеть подставляет SSID
  в поле и переводит курсор в поле пароля. Сканирование асинхронное — точка
  доступа не отваливается, страница продолжает работать.
* **Помпы** — GPIO для каждого канала, **имя канала** (что он поливает) и инверсия
  (включение низким уровнем). Имя сохраняется **сразу после ввода** (уход с поля),
  пины и инверсия — кнопкой «Сохранить настройки».
* **Датчик уровня** — GPIO, внутренняя подтяжка, полярность сигнала, запрет
  полива при низком уровне.
* **Время и защита** — NTP-сервер, часовой пояс в формате UTC (`UTC+00:00`, `UTC+03:00 (Москва, МСК)`,
  …; по умолчанию **UTC+3, МСК**), кнопки передачи времени с телефона, максимум секунд
  на включение, догоняющий полив. Рядом показано текущее время контроллера и источник
  времени (NTP / телефон / нет).
* **Обновление прошивки** — выбор файла `.bin` и кнопка «Обновить прошивку»:
  полоса показывает, сколько уже отправлено, затем модуль перезагружается в новую
  версию. Полив на время обновления останавливается. Рядом написано, сколько
  свободно под новый образ и какая версия сейчас на модуле. Подробнее —
  в разделе «Обновление прошивки по Wi-Fi».
* **Резервная копия** — «Скачать файл настроек» (JSON со всеми настройками, именами
  каналов и задачами) и «Загрузить из файла» (импорт на этот или другой модуль).
  Галочка «Переносить статус задач» решает, брать ли из файла время последнего и
  следующего полива: снятая — расписание начнётся заново от текущего времени, так
  удобнее клонировать конфигурацию на второй контроллер. Wi-Fi (сеть и пароль)
  в файл не выгружается; при импорте текущие настройки и задачи заменяются целиком.
* **Информация** — имя модуля, версия, режим Wi-Fi, IP, сырое значение датчика, память, uptime.
* **Опасная зона** — перезагрузка и сброс к заводским настройкам.

## Защита и предохранители

* **Низкий уровень воды** — пуск блокируется, а начатый полив немедленно
  прекращается (если включена опция «Блокировать полив при низком уровне»).
* **Максимальная длительность** (`maxRunSec`, по умолчанию 600 с) — жёсткое
  ограничение на любое включение канала, включая ручное и по задаче.
* **Аварийное выключение при потере питания** — после перезагрузки все каналы
  выключены (реле обесточены).

## REST API

Все запросы — `application/x-www-form-urlencoded`, ответы — JSON.

| Метод | URL | Параметры | Назначение |
|---|---|---|---|
| GET | `/api/state` | — | Время, датчик, Wi-Fi, каналы, задачи |
| GET | `/api/config` | — | Настройки (включая `name` модуля и `ch[].name` каналов) |
| GET | `/api/scan` | `start=1` — начать поиск | Список Wi-Fi сетей: `{state:"running"/"done"/"idle", count, nets:[{ssid, rssi, enc}]}` |
| POST | `/api/task` | `id` (-1 = новая), `ch`, `hour`, `min`, `dur`, `period`, `enabled` | Создать/изменить задачу |
| POST | `/api/task/del` | `id` | Удалить задачу |
| POST | `/api/task/run` | `id` | Ручной пуск задачи |
| POST | `/api/ch` | `ch`, `sec` (0 = стоп) | Ручной пуск/остановка канала |
| POST | `/api/config` | `name`, `chN_pin`, `chN_inv`, `chN_name`, `sensorPin`, `sensorInv`, `sensorPull`, `blockLow`, `maxRun`, `catchup`, `ntp`, `tz` | Сохранить настройки (можно передать только `name` — остальное останется как было) |
| POST | `/api/time` | `now` (unix UTC), `tz` (минуты, необязательно) | Установить время с телефона (и при желании часовой пояс) |
| GET | `/api/export` | — | Настройки и задачи одним JSON-файлом (без Wi-Fi), отдаётся с `Content-Disposition: attachment` |
| POST | `/api/import` | `name`, `tz`, `ntp`, `sensorPin`, `sensorInv`, `sensorPull`, `blockLow`, `maxRun`, `catchup`, `chN_pin`, `chN_inv`, `chN_name`, `t0…t7` («`ch,h,m,dur,pd,en,last,next`»), `status` (1 = переносить статус задач) | Импорт из файла: всё проверяется до применения, при ошибке настройки не меняются |
| GET | `/api/ident` | — | Визитка для сканера сети: `{app:"autowatering", fw, name, ch, ip}` — короткая, её спрашивают у каждого адреса подсети |
| GET | `/api/ota` | — | Состояние обновления: `{fw, state, stateText, received, total, maxSize, minSize, freeHeap, err}` (`state`: 0 простаивает, 1 идёт приём, 2 готово, 3 ошибка) |
| POST | `/api/ota` | `multipart/form-data`, поле `firmware` = файл `.bin` | Обновление прошивки по Wi-Fi: файл пишется во flash, модуль перезагружается. Ответ: `{ok:true,size}` или `{ok:false,error}` |
| POST | `/api/wifi` | `ssid`, `pass` | Сохранить Wi-Fi и перезагрузиться |
| POST | `/api/factory` | — | Сброс к заводским настройкам |
| POST | `/api/reboot` | — | Перезагрузка |

Ошибки: `{"ok":false,"error":"low_water"}` (HTTP 409) и подобные.

Все ответы `/api/*` отдаются с `Access-Control-Allow-Origin: *`, а на `OPTIONS`
приходит ответ 204 с разрешёнными методами (и `Access-Control-Allow-Private-Network`
для Chrome). Без этого чужая страница — интерфейс соседнего модуля или страница
проекта — не смогла бы ни найти модули в сети, ни отправить им прошивку.
Побочный эффект: любая страница в этой сети может дёргать API модуля. Устройство
и так без авторизации, поэтому рассчитывайте на доверенную домашнюю сеть.

## Резервная копия и перенос между модулями

Экспорт — это обычный JSON, его можно открыть и поправить руками:

```json
{
  "app": "ESP8266-Autowatering2", "fw": "1.5.0", "sv": 3,
  "exported": "24.11.2026 12:00:00",
  "cfg": {
    "name": "Теплица", "tz": 180, "ntp": "pool.ntp.org",
    "sensorPin": 13, "sensorInv": 1, "sensorPull": 1, "blockLow": 1,
    "maxRun": 600, "catchup": 6,
    "ch": [{"pin": 4, "inv": 0, "name": "Орхидеи"}, …]
  },
  "tasks": [
    {"ch": 0, "h": 8, "m": 0, "dur": 30, "pd": 1, "en": 1, "last": 0, "next": 0}
  ]
}
```

Wi-Fi в файл не попадает: после импорта на новом модуле сеть указывается отдельно
(в настройках есть кнопка «Сканировать»). Перед импортом показывается подтверждение
с числом задач; при ошибке (битый JSON, недопустимый пин, длительность больше
предохранителя) прошивка отвечает кодом ошибки и **не меняет** текущую конфигурацию.

## Хранение настроек

Настройки и задачи хранятся одной структурой `Store` (см. `src/app_config.h`) в
секторе эмуляции EEPROM, защищённой CRC32 и magic-числом. При первом старте или
повреждении данных автоматически восстанавливаются умолчания.

Сохраняется в том числе:

* `lastRun` — время последнего полива задачи (это и есть «статус»);
* `nextDue` — время следующего планового полива (чтобы расписание не «плыло»
  после перезагрузки).

Оба значения хранятся в **местной шкале** (wall clock по выбранному часовому поясу),
поэтому смена пояса не сдвигает расписание: задача «08:00» остаётся на 08:00.
Версия формата хранилища — 3 (в версии 3 добавлены имена модуля и каналов): при
обновлении с более старых версий настройки сбрасываются к умолчаниям, в том числе
пояс UTC+3 по умолчанию. Имена хранятся в UTF-8, максимум 32 байта на поле
(около 16 символов кириллицы); при сохранении строка обрезается по границе
символа, чтобы в интерфейсе не появлялась битая кодировка.

## Сборка

### Вариант 1: PlatformIO (рекомендуется)

```bash
pio run                # сборка
pio run -t upload      # прошивка (порт COM7, 921600 — см. platformio.ini)
pio device monitor     # лог 115200
```

`tools/pio_embed_web.py` автоматически пересобирает `src/page_html.h` из
`web/index.html` перед сборкой.

### Вариант 2: `tools/build_firmware.sh` (без PlatformIO)

Скрипт собирает прошивку напрямую кросс-компилятором xtensa-lx106-elf-g++ и
ядром Arduino-esp8266 2.4.2 (именно так собран бинарник в `firmware/`):

```bash
TOOLCHAIN_DIR=$HOME/tools/xtensa-lx106-elf \
CORE_DIR=$HOME/tools/Arduino-2.4.2 \
./tools/build_firmware.sh
```

Результат: `firmware/autowatering-esp8266.bin` + `firmware/build-info.txt`.

### Правка интерфейса

Интерфейс — `web/index.html` (чистый HTML/CSS/JS, без сборщиков), упаковывается
в `src/page_html.h` gzip-ом:

```bash
python3 tools/embed_web.py
```

### Тесты логики (без железа)

```bash
make -C tests/host run      # storage/CRC, помпы, планировщик, обмен, JSON, проверка файла OTA
```

Тесты собирают настоящий JSON `/api/state`, `/api/config` и `/api/export` и
проверяют его парсером Python (`tests/host/check_json.py`) — так ловится
потерянное или переименованное поле, которое при сборке прошивки никак не
проявляется (например, `nm` с именем канала).

## Прошивка

```bash
pip install esptool
./tools/flash.sh            # COM7, 921600
./tools/flash.sh /dev/ttyUSB0 460800
```

Windows: `tools\flash.bat` (по умолчанию COM7, 921600).

Или вручную:

```bash
esptool.py --chip esp8266 --port COM7 --baud 921600 \
  write_flash --flash_mode dout --flash_freq 40m --flash_size 4MB \
  0x00000 firmware/autowatering-esp8266.bin
```

Образ уже содержит загрузчик `eboot` (адрес 0x0) и приложение (адрес 0x1000),
поэтому прошивается одним файлом с `0x00000`.

## Обновление прошивки по Wi-Fi

Начиная с 1.6.0 прошивку можно обновлять по сети, без кабеля:

1. Скачайте новый `autowatering-esp8266.bin` (папка `firmware` в репозитории).
2. Откройте веб-интерфейс контроллера → «Настройки» → «Обновление прошивки».
3. Выберите файл и нажмите **«Обновить прошивку»**, подтвердите.
4. Дождитесь надписи «Прошивка принята… модуль перезагружается»: страница сама
   перезагрузится, когда модуль снова ответит. Обычно это 20–60 секунд.

Что важно знать:

* **Полив останавливается** на время обновления: пока прошивка пишется во flash,
  контроллер не выполняет основной цикл, и оставленная включённой помпа могла бы
  залить грядку. После перезагрузки расписание продолжается как обычно.
* **Настройки, задачи и имена каналов сохраняются** — они лежат в отдельном
  секторе flash, который обновление не трогает.
* **Старая прошивка остаётся целой, пока новая не принята полностью.** Если файл
  не тот, связь оборвалась или места не хватает, модуль продолжает работать на
  прежней версии и пишет причину в карточке обновления (и в Serial 115200).
* Нужен именно файл `.bin` этого проекта (не `.elf`, не `firmware.bin` от других
  плат). Файл меньше 32 КБ или больше свободного места отклоняется ещё до записи.
* Обновление работает по Wi-Fi; если модуль поднял точку доступа `AutoWater-XXXXXX`,
  сначала подключите его к сети (или обновляйте, находясь в его точке доступа).
* **Первый переход на 1.6.0** делается один раз по USB: в прошивках до 1.6.0 этой
  функции просто нет. Дальше — по сети.

Через `curl` (если интерфейс не под рукой):

```bash
curl -F firmware=@firmware/autowatering-esp8266.bin http://192.168.1.50/api/ota
```

Технически: браузер отправляет файл на `POST /api/ota`, контроллер пишет его в
свободную область flash (между текущей прошивкой и разделом SPIFFS) порциями по
2 КБ, затем ставит загрузчику `eboot` команду «скопировать принятый образ в начало
flash и запустить». Поэтому обновление не требует второй копии прошивки в обычной
памяти и не может «окирпичить» модуль при обрыве связи. Размер свободной области
(~700 КБ при текущих ~319 КБ прошивки) виден в карточке обновления.

После прошивки: Serial 115200, скорость загрузки 921600 (в `platformio.ini`).

## Страница проекта (`docs/`)

Для тех, кто просто хочет взять прошивку, есть отдельная страница — [`docs/index.html`](docs/index.html):
описание возможностей, экраны интерфейса, быстрая установка, блок обновления и кнопка скачивания `.bin`.
Страница — статический HTML без внешних CDN и сборки; единственный скрипт на ней — прошивальщик
(см. ниже), он загружается только по нажатию кнопки, поэтому сама страница остаётся лёгкой.

### Прошивка по USB прямо со страницы

В разделе «Прошивка» страница сама пишет `.bin` в плату: Web Serial + [esptool-js](https://github.com/espressif/esptool-js),
ни esptool, ни Python, ни Arduino IDE на компьютере не нужны.

* Работает в Chrome, Edge и Opera на компьютере (мобильные браузеры Web Serial не поддерживают),
  страница должна быть открыта по `https://` или на `localhost`.
* Порт спрашивается первым делом, файл скачивается после — браузер даёт доступ к USB только
  сразу после нажатия кнопки.
* Перед записью MD5 скачанного файла сверяется со значением на странице, после записи esptool-js
  сверяет MD5 с платой; стираются только нужные сектора (`eraseAll: false`), образ пишется
  с адреса `0x00000` в режиме `dout`/40 МГц под 4 МБ flash. После прошивки — аппаратный сброс
  и обычная загрузка.
* Если браузер не умеет Web Serial, кнопка выключается и показывается команда `esptool` из раздела
  «Установка» — страница деградирует, но не ломается.

### Обновление других модулей в сети

Раздел «Обновить модули в сети» на странице находит уже прошитые автополивы в той же
сети и обновляет выбранный по Wi-Fi: тот же протокол, что и в интерфейсе модуля
(`GET /api/ident` для поиска, `POST /api/ota` для файла). Найденные модули видны
с именем, адресом и версией; рядом — метка «актуально» или «можно обновить до X».
Если интернета нет, вместо файла из репозитория можно выбрать свой `.bin`.

Ограничение браузера, о котором стоит знать: со страницы по `https` (GitHub Pages)
запросы к модулям по `http` в локальной сети Chrome может заблокировать как mixed
content. Поэтому тот же сканер живёт и в интерфейсе модуля («Настройки» → «Другие
модули в сети», страница открыта по http с самого устройства) — оттуда обновление
проходит всегда. Страница проекта по `http://` (локально, `python3 -m http.server
-d docs 8000`) сканирует сеть сама.

Прошивальщик — отдельный бандл:

```bash
npm i esptool-js crypto-js esbuild      # одноразово, в репозитории зависимостей нет
node tools/build_flasher.js             # tools/flasher/src/flasher.js -> docs/js/flasher.js
```

Исходник — [`tools/flasher/src/flasher.js`](tools/flasher/src/flasher.js), собранный файл
`docs/js/flasher.js` руками не правят. Копию `.bin` для страницы кладёт `tools/update_docs.py`
(`docs/firmware/autowatering-esp8266.bin`), поэтому на GitHub Pages прошивка доступна с того же
домена и без внешних ссылок.

Как открыть:

* **GitHub Pages** (рекомендуется): Settings → Pages → Source: «Deploy from a branch»,
  ветка `main`, папка `/docs`. Адрес получится `https://<владелец>.github.io/ESP8266-Autowatering2/`.
* Либо локально: `python3 -m http.server -d docs 8000` и открыть `http://localhost:8000/`.

Как поддерживать в актуальном виде:

| Что | Чем |
|---|---|
| Скриншоты (`docs/img/*.png`) | `node tools/screenshots.js` — снимает **настоящий** `web/index.html` с подменённой сетью (Chromium через `puppeteer-core`), кадры: задачи, каналы, настройки, карточка обновления, первый запуск, «другие модули в сети», общий вид |
| Версия, размер, MD5, дата на странице | `python3 tools/update_docs.py` — берёт цифры из `firmware/build-info.txt` и кладёт копию `.bin` в `docs/firmware/`; `--check` только сверяет (в т. ч. что копия совпадает по MD5) |
| Прошивальщик (`docs/js/flasher.js`) | `node tools/build_flasher.js` — esbuild собирает `tools/flasher/src/flasher.js` вместе с esptool-js; нужны `npm i esptool-js crypto-js esbuild` |
| Тексты, разделы | руками в `docs/index.html` |

Скриншоты снимаются не «на память», а с живого интерфейса, поэтому после правок в
`web/index.html` их достаточно перегенерировать: `python3 tools/embed_web.py`,
затем `node tools/screenshots.js`, затем `python3 tools/update_docs.py`.

Для `tools/screenshots.js` нужны одноразовые зависимости:

```bash
npm i puppeteer-core @sparticuz/chromium   # или CHROME=/usr/bin/chromium node tools/screenshots.js
```

## Ограничения

* Часовой пояс — фиксированное смещение от UTC (шаг 30 минут), автоперехода на
  летнее время нет: при необходимости поменяйте пояс вручную.
* У ESP8266 нет часов с батарейкой: после включения время берётся по NTP, а без
  интернета — с телефона (кнопка в шапке/настройках). Время, переданное
  с телефона, живёт до перезагрузки; пока время неизвестно, задачи не выполняются.
* В интерфейсе все моменты времени приходят с устройства уже в виде строк
  (`18.11 08:00`) — браузер не пересчитывает их в свой часовой пояс.
* Задачи — до 8 штук, каналы — 4.
* Web-интерфейс без авторизации: поднимайте устройство в доверенной сети.
* CORS открыт (`Access-Control-Allow-Origin: *`) — иначе сканер сети и обновление
  соседних модулей из браузера не работают. Любая страница в той же сети может
  обратиться к API модуля; это осознанный выбор в пользу «работает без установки».
